# 修订与验收

用于续改、重排、引用范围、脱敏及最终导出。目标是保留已认可内容，只改变本轮确实需要改变的部分。

## 确认基线和修改边界

实读用户最新提供或确认的文件；文件名“终稿”、旧缩略图和上一轮完成声明不能替代读取。源文件只读，副本使用新文件名。项目有Codex目录时沿用已有归档结构，不层层叠加审计包。

反馈分为全局格式、局部文案、图片、引用锚点、导航和页序。建立原页—新页对应表，先按原逻辑页找到对象，再删并移动；不按slideN.xml名称或移动后的页码猜测用户指向。

页码有歧义时，用标题、图片内容和相邻页核对语义身份，再落实映射。保持指定模板的背景、承托形状、重点色、字体层级、封面和封底；“减少拥挤”或“美化”不等于另造一套空白模板。明确区分用户要求保留的原页、合并后的页面和本轮新增页。

局部修订不重新引入已删除页、长说明、模型或科学分支。图表只需要改字体时不重算数据；确需重算，分别记录数据/统计/图形层变化。用户要求删除半句后，应再检查剩余句的自然换行和孤字末行。

## 重排的必要联动

保留各页的原资源和备注关系，更新演示逻辑顺序、可见页码、小节号、当前导航、相关跳转和备注中的页码。还需检查原生section、自定义放映、动画和媒体是否存在；不承诺未经验证的功能保留。

备份页进入正文后删除“备份”说明，采用合适小节号/导航；研究的版本及发表状态仍保持。导出PDF应来自最终顺序，而不是旧PDF简单重排后冒充最新文本。

分别核对正文页、隐藏页和总页数。“删除备答页”应实际删除，不能仅隐藏；同步检查section、自定义放映及内部链接。清理无引用资源前先核对共享关系，避免删掉其他页面仍使用的媒体。

## 超链接验收：检查真实点击范围

1. 引用完整题名仍可见；只让期刊/机构/平台名链接。
2. 字重、字体、字号与周围引用一致；锚点加粗、无下划线。
3. 题名、前缀、年份、标点、Reviewed Preprint/v2等不属于点击文字。
4. 检查run的click/mouseover，以及形状级动作，不能只凭蓝色外观。
5. 每一锚点的目标与该条来源对应；不要把一个DOI复用到其他论文。
6. PDF导出后核对注释矩形，尤其名称紧邻标点、跨行和多篇引用的情况。

精确引用映射与只读脚本见[模板配置](template-profile.md)。结构检查可以发现题名误链接，但不能代替来源内容核对。

## 两层检查

**结构检查**：ZIP完整性、逻辑页数、对象和资源关系、显式字号、有限模板字段、引用run、精确锚点映射及原文件指纹。未改图片可以比较二进制是否一致。母版继承、组合变换等未被工具覆盖时，不作完全通过声明。

**视觉检查**：从最终PPTX导出的PDF或实际渲染查看，而不只看编辑工具中的预览。

| 层级 | 重点 |
|---|---|
| 整套联系表 | 顺序、章节、导航、页码、字体层级和主要图组节奏 |
| 所有受影响页大图 | 标题与横线、内容左右界、图注中心、引用末行与页码 |
| 密集图与表 | 坐标、标签、标尺、表头、数字和来源是否被裁切或重叠 |
| 文本 | 去掉多余硬换行，避免一两字孤行、缺字方框和无意义小字 |
| 科学内容 | 数据来源、原文结果/再分析/计划的身份，实际n、分母、单位和方向 |
| 最终附件 | PPTX和PDF页数/顺序一致，链接实际可用，文本/表格保持可编辑 |

全局改动检查所有受影响页。局部修改可比较前后截图以定位意外变化，但渲染器差异引起的像素差异不自动等于内容错误。静态渲染不能证明媒体播放正常。

对局部修改比较包内改动清单，核对未要求变动的正文、资源、动画和媒体关系；必要时以相同软件、字体和导出设置复核未改页。ZIP部件、文本或边界一致，只证明相应层面未变，不能据此宣称最终视觉完全一致。字体覆盖、无溢出也不能排除错字形；原生渲染异常见[媒体与渲染](media-and-rendering.md)。

混合字号底端、组合中心、数字与说明的间距需要同时检查真实呈现和几何约束。可使用[渲染后边界检查](rendered-layout-checks.md)验证测得的边界，但不把文本框居中当作字形居中，也不以自动报告替代看图。

## 脱敏与素材保护

仅在当前任务要求时脱敏。确认哪些字段应隐藏、哪些保留；不能根据模糊照片猜身份。图像脱敏应写入副本像素，不只放可移除遮挡层。同步检查备注、替代文字、隐藏对象、嵌入附件和未脱敏原件是否仍可提取。

原图保真与脱敏可以兼容：只处理指定区域，其他证据不重排。若只能展示遮挡，就明确这一范围，不宣称不可恢复。不要继承历史比赛的遮挡名单。

## 音视频按需验证

不自动增加背景音乐、自动翻页或动画。需要时明确开始/停止、循环、跨页及音轨规则，在目标软件中试播。无法实际试播时如实写“媒体播放未实测”，不以XML属性或静态PDF证明成功。默认保留已认可备注与媒体，不因历史任务曾清空而照做。

多媒体较多时用一张私有时间表记录每个对象的开始、结束、音轨、循环和翻页条件；裁剪与拼接后重新核对时长及自动跳转。片头顺序播放、跨页音乐、正文静音和有声片尾之间的冲突按本轮要求解决，详细流程见[媒体与渲染](media-and-rendering.md)。

仅在用户授权后清理过时生成版本：先验证最新成品及保存位置，限定实际目标目录，保留用户原件和仍依赖的素材；删除前核对解析后的绝对路径。版本清理不属于每次交付的默认步骤。

## 公共仓库更新

写入前读取当前分支和文件内容，保留与本轮无关的规则。记录通用原则与可选profile，不提交私人研究结论、供者/患者数据、演示PPT、字体、大学logo、原文Figure或截图。

仅提交通用UTF-8文档、配置、脚本和合成测试。读取返回的文件SHA及分支头后更新，提交时校验预期分支头，不盲目覆盖并发修改；发生变化先核对并合并。不因任务涉及GitHub而修改仓库可见性或发布二进制附件。

代码测试用合成OOXML构造边界情况：题名误链接、状态误链接、形状级动作、错误页码/字号、逻辑页序和源文件只读。测试通过只说明这些逻辑；不等于完成视觉、事实或Office兼容性认证。

提交后读回树/关键文件，核对实际commit及改动范围，再报告完成；本地准备好但未成功写入，必须明确区分。更新Skill后原有项目文件不自动改变。

## 克制交付

交付真实存在、可打开的PPTX；需要时提供同版PDF。用户要求讲稿/手册时再同步维护，否则不为小改动再生成一大套Word、Excel和审计附件。

内部素材表、程序日志、临时渲染和引用映射默认留在当前私有工作区。最终回复给成品、实际变化、仓库提交和仍未完成的必要事项。只声称实际执行过的导出、查看或试播。
