# 模板配置与复用

## 三层内容，避免把一次汇报写死

1. **通用原则**：真实证据、问题驱动、最小必要修改、统一图组、光学对齐、实际导出验证。
2. **可选profile**：用户明确沿用某套模板时，采用该模板的字号、边界和组件规则。
3. **当次素材与科学内容**：题目、数字、论文、图、模型、日期和署名，仅属于当前任务，不提交到公共Skill。

[clinical-academic.json](../profiles/clinical-academic.json)是已确认的蓝白学术模板profile。它记录16:9页面、华文楷体、#074591、导航14 pt、页脚9 pt、标题24 pt及少量测量边界。**它不是模板PPTX本身**；必须由用户提供真实模板和必要字体/校标。仓库只存参数，不能从参数重新伪造原模板。

## 应用流程

读取最新PPT并渲染典型页 → 明确选择profile → 对比尺寸和现有角色 → 局部修订 → 核对页序与引用 → 从最终PPT导出PDF并检查。

页面尺寸不符时重新量取，不直接等比缩放全部文字。用户的新要求可覆盖profile，但应同步记录本轮生效值。没有选择profile时保留通用建议，不自动施加14/9 pt。

profile里的形状名用于该模板的只读检查，例如`ReferenceFooter`、`TextBox 7`。换模板必须核对或更改这些键；通用名称不代表在每个PPT里都有同一含义。

## 精确引用范围

推荐用三到四个独立run：

```text
[数据来源：] [完整论文题名 | ] [期刊名] [, 年份.]
```

仅第三个run链接，其余不链接。`eLife Reviewed Preprint v2`应拆成`eLife`和` Reviewed Preprint v2`；状态保留在可见文本中，但不进入点击范围。官方来源采用相同方法，仅机构/平台名链接。

`a:rPr/a:hlinkClick`之外，也检查`a:hlinkMouseOver`和`p:cNvPr`下的形状级动作。移除文本链接但保留整框点击，不算完成。

复杂情形可以在本地准备精确引用映射，例子见[examples/citation-map.example.json](../examples/citation-map.example.json)：

```bash
python scripts/lint_pptx_style.py deck.pptx \
  --profile profiles/clinical-academic.json \
  --citation-map local/citation-map.json
```

映射键为`逻辑页码:形状名:段落序号`（均从1开始）。值按顺序写出允许点击的文字与目标URL。使用最终顺序生成该文件，移动页面后不能沿用旧页码。

无映射时，脚本可发现题名/年份/状态误链接、隐藏形状动作等常见问题；**不能自动猜出所有合法期刊名或证实URL内容对应性**。有映射时才能精确比较锚点文本和目标。

## 修改页面顺序

先记录原页—新页表。OOXML中的`ppt/presentation.xml`及其关系表确定逻辑顺序，不按`slide1.xml`文件名排序。移动后保留原页资源和备注关系，更新可见页码、小节号、导航和需要调整的说明；有原生章节、custom show或内部跳转时也检查它们。未检测这些部件的脚本不能宣称已经验证。

从备份移入正文时只改变演示身份，不改变论文状态。删除文末半句后应重新检查短行，必要时同义精简剩余句子。

## 工具能力边界

`inspect_pptx.py`：结构与显式属性盘点，正文仅在`--include-text`时导出。

`lint_pptx_style.py`：只读检查逻辑页序相关页码、明确导航/引用字号、页脚点击范围及可选精确映射。默认不修改文件、不联网，也不输出整段正文。退出码0表示未发现已实现检查项的错误，1表示发现错误，2表示输入/读取失败。继承字号和未显式加粗等可能以警告报告。

该检查器不验证事实、不审图、不处理所有Office继承样式，也不检测真实字形的裁剪/下划线。PDF导出后仍应检查真实点击矩形、全套联系表和受影响页大图。几何profile提供制作参照，不表示每个字段都由脚本自动验证。
