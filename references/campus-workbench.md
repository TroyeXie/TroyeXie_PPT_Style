# 校园工作台与 Skill 协作

在课程汇报、组会汇报或文献分享需要可操作原型时，使用 `app/index.html`。制作原文件的精确续改时，继续遵循原 Skill 的模板与最小修订规则。

## 明确当前能力

- 使用场景结构、主题参数、章节、逐页内容和来源构成项目模型。
- 用 TXT／Markdown 提纲直接排页，或让用户将 `buildPrompt` 生成的任务包交给现有 AI 助手，导入返回 JSON。
- 将 AI 协作明确说明为外部助手参与。没有实际调用模型时，不显示“模型已分析”“文献已核实”等状态。
- 模板导入只读取首个母版对应主题的字体、两项强调色和页面尺寸。不得称为完整保留母版或任意模板无损迁移。
- 使用合成教学示例进行公开演示。保持来源图、个人汇报、字体与模板原件在用户当前工作区。

## 结构化返回

遵循 `app/core.js` 的 `normalizeProject` 格式，顶层为 `version:1`、`title`、`presenter`、`scene`、`duration`、`theme` 和 `slides`。保留页面 `id`，以便局部编辑和按 ID 保留图片。`scene` 为 `course`、`lab` 或 `journal`。

每页指定 `type`、`section`、`title`、`body`、`citations`、`notes`、`evidence` 和 `durationSec`。比较页用两个 `columns`；图文页记录 `caption`。支持封面、章节、要点、比较和图文布局，不构造运行时不支持的图表或复杂表格字段。

`citations` 逐条记录完整题名 `title`、期刊或机构名 `venue`、年份 `year`、完整网址 `url`、来源类别 `kind` 与发表状态 `status`。图片外部协作时保持 `image:null`；粘贴导入 AI 结果会按相同 ID 保留当前原图。新上传的项目 JSON 按其自身内容打开，不把旧项目图片混入新项目。

将文献结果、本项目分析、假说、计划与教学内容分别标记。确需说明的限制放在页面或讲稿中，不能用空来源或链接形式掩盖证据缺失。

## 检查与交付

运行 `node app/tests.mjs` 核查项目与导出结构，按需要运行原有 Python 检查器。新增或变更版面后导出真实 PPTX，渲染典型页检查。分别说明自动结构检查、渲染检查和实际软件操作的完成范围。

用户输入错误时保留当前项目并显示具体原因。不要静默删除无法识别的段落、引用或图像。浏览器保存失败时提示导出项目，不能声称已保存。

修改代码后仅提交应用、通用规范与合成示例，保留开源依赖许可证；不向公开仓库提交真实材料和运行时文件。参赛成效依据实际试用记录，不将历史人工制作的 PPT 写成应用已完成案例。
